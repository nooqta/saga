# SRS Generation

You are generating a Software Requirements Specification (SRS) document for a SAGA project.

## Pre-requisites

1. Check if `.saga/project.json` exists
   - If not: "Please run `/saga init` first to initialize your project."

2. Read project context from `.saga/project.json`

## Generation Process

### 1. Gather Requirements

If no argument provided, ask the user:
- "What are we building? Describe the main functionality."
- "Who are the primary users?"
- "What are the key features you need?"
- "Are there any constraints or non-functional requirements? (performance, security, etc.)"

If argument provided, use it as the starting point and ask clarifying questions.

Create `.saga/srs.md` with the following structure:

## Requirement ID Format

- **FR-XXX**: Functional Requirements (FR-001, FR-002, etc.)
- **NFR-XXX**: Non-Functional Requirements (NFR-001, NFR-002, etc.)

## Quality Guidelines

When generating requirements:

1. **Specific**: Each requirement should be clear and unambiguous
2. **Measurable**: Include acceptance criteria that can be verified
3. **Achievable**: Requirements should be technically feasible
4. **Relevant**: Each requirement should trace to a user need
5. **Traceable**: Use consistent ID format for later traceability

## After Generation

1. Display summary:
   ```
   SRS Generated: .saga/srs.md

   Requirements Summary:
   - Functional Requirements: X
   - Non-Functional Requirements: Y
   - System Features: Z

   Next steps:
   - Review the SRS and make any adjustments
   - Run /saga plan to create the implementation plan
   - Run /saga diagram to generate UML diagrams
   ```

2. If PM integration is configured (GitHub/GitLab):
   - Ask: "Would you like me to create an Epic issue for this SRS in [platform]?"
   - If yes, use pm-workflow skill to create the epic

## Iterative Refinement

If user wants to refine:
- "Would you like to add more requirements?"
- "Should I break down any requirements further?"
- "Are there any requirements that need clarification?"

Read existing `.saga/srs.md` and append/modify as needed.
