# SAGA Project Initialization

You are initializing a new SAGA project. Guide the user through setup with a conversational approach.

## Setup Flow

### 1. Create Directory Structure

First, create the `.saga/` directory structure:

```bash
mkdir -p .saga/diagrams .saga/changes .saga/hooks
```

### 2. Gather Project Information

Ask the user conversationally:

**Project Basics:**
- "What's the name of your project?"
- "Can you give me a brief description? (1-2 sentences)"

### 3. PM Tool Configuration

Ask the user about PM tool integration:

**Platform Selection:**
- "Would you like to integrate with a PM tool? Options: GitHub, GitLab, or None"

**If GitHub or GitLab selected:**

1. **Auto-detect from git remote:**
   ```bash
   git remote get-url origin 2>/dev/null
   ```
   - Parse the URL to extract organization/project
   - Suggest: "I detected your repo is at `org/project`. Is this correct?"

2. **Token Configuration:**
   - Ask: "Do you have a token configured in your environment?"
   - For GitHub: Check `GITHUB_TOKEN` or `GH_TOKEN`
   - For GitLab: Check `GITLAB_TOKEN` or `GL_TOKEN`
   - If not found: "Please set `GITHUB_TOKEN` (or `GITLAB_TOKEN`) in your environment"

3. **Workflow Definition:**
   Ask what should happen at each lifecycle event:

   - "When a story starts, should I create an issue? Add labels?"
   - "When a story completes, should I close the issue? Create a merge/pull request?"
   - "When a story is blocked, should I add a 'blocked' label? Add a comment?"
   - "When a change request is created, should I create an issue?"

### 4. Create project.json

Based on gathered information, create `.saga/project.json`:

```json
{
  "name": "Project Name",
  "description": "Project description",
  "createdAt": "2024-01-15T10:00:00Z",
  "pm": {
    "platform": "github" | "gitlab" | "none",
    "url": "https://github.com",
    "project": "org/repo",
    "token_env": "GITHUB_TOKEN",
    "workflow": {
      "on_story_start": {
        "create_issue": true,
        "add_labels": ["in-progress", "saga"]
      },
      "on_story_complete": {
        "close_issue": true,
        "create_mr": true,
        "add_labels": ["done"]
      },
      "on_story_blocked": {
        "add_labels": ["blocked"],
        "add_comment": true
      },
      "on_cr_created": {
        "create_issue": true,
        "add_labels": ["change-request"]
      }
    }
  },
  "settings": {
    "tddRequired": true,
    "autoPush": false,
    "executionMode": "sequential",
    "evaluatorEnabled": true,
    "allowReorder": true,
    "evaluateEveryNIterations": 3,
    "maxRetries": 3
  }
}
```

### 5. Create Initial Files

Create placeholder files:

**`.saga/srs.md`** (empty template):
```markdown
# Software Requirements Specification

> Generated by SAGA - Run `/saga spec` to populate

## 1. Introduction

### 1.1 Purpose
<!-- Purpose of this document -->

### 1.2 Scope
<!-- Scope of the project -->

### 1.3 Definitions
<!-- Key terms and definitions -->

## 2. Overall Description

### 2.1 Product Perspective
<!-- How this product fits in the larger context -->

### 2.2 User Characteristics
<!-- Who will use this product -->

### 2.3 Constraints
<!-- Technical and business constraints -->

## 3. Functional Requirements

<!-- FR-001: Requirement description -->

## 4. Non-Functional Requirements

<!-- NFR-001: Requirement description -->

## 5. Acceptance Criteria

<!-- Acceptance criteria per requirement -->
```

**`.saga/progress.txt`**:
```
# SAGA Progress Log

## Codebase Patterns
<!-- Add reusable patterns discovered during development -->

---

```

### 6. Create .gitignore

```
# SAGA runtime artifacts
state.json
metrics.jsonl
```

### 7. Output Summary

After setup, display:

```

Project: [name]
Description: [description]
PM Integration: [platform] ([project])

Files created:
  .saga/project.json    - Project configuration
  .saga/srs.md          - SRS template (run /saga spec to populate)
  .saga/progress.txt    - Progress tracking

Next steps:
  1. /saga spec         - Generate Software Requirements Specification
  2. /saga plan         - Create Epic/Feature/Story hierarchy
  3. /saga execute      - Start autonomous execution
```

## Validation

Before completing, validate:
- [ ] `.saga/` directory exists
- [ ] `.saga/project.json` is valid JSON
- [ ] PM token exists in environment (if PM configured)
- [ ] Git remote URL matches configured project (if PM configured)

## Error Handling

If issues detected:
- Missing token: Warn but continue (can be set later)
- Invalid git remote: Ask user to confirm project path manually
- Existing project.json: Ask "A SAGA project already exists. Overwrite? (y/n)"
